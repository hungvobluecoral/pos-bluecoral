## Challenges — Điều cần cải thiện

### 1. 🚨 Thiếu Next.js proxy config (Critical — đã fix)
- **Vấn đề:** `apps/web/next.config.js` không có `rewrites`, khiến client-side `fetch('/api/...')` gọi vào Next.js thay vì NestJS.
- **Hậu quả:** UI không thực sự giao tiếp với backend suốt Epic 1. Chỉ phát hiện sau khi test manual.
- **Fix đã apply:** Thêm `rewrites` proxy `/api/:path*` → `INTERNAL_API_URL/api/:path*` vào `next.config.js`.
- **Root cause:** Không có E2E integration test nào verify UI-API connection thực sự.

### 2. Error code format không nhất quán
- Xuất hiện ở Story 1.1 (snake_case vs camelCase) và lại ở Story 1.4 (camelCase vs kebab-case).
- `NEXT_PUBLIC_API_BASE_URL` được define trong `.env` nhưng không được dùng ở bất kỳ đâu trong client code.

### 3. Không có E2E integration test với server thật
- Tất cả tests chạy với mock API — không có test nào verify full request từ browser → NestJS → PostgreSQL.
- Proxy bug không bị catch bởi bất kỳ test nào.

### 4. UX spec gaps ở Story 1.3
- Tablet progressive collapse: spec yêu cầu nhưng không được implement.
- Readiness impact: chỉ hiện ở side panel, chưa inline cạnh field lỗi như spec.

## Key Insights

1. **"Tests xanh" không có nghĩa là "flow hoạt động"** — proxy bug là ví dụ rõ ràng nhất. Cần ít nhất 1 smoke test end-to-end thực sự cho mỗi epic.
2. **API integration pattern cần được document rõ** — 2 pattern (client-side fetch vs server-side fetch) không được ghi lại, gây confusion cho team mới.
3. **Error code standardization phải được enforce ngay từ đầu** — khi để drift qua nhiều stories, sửa lại tốn công hơn.
4. **Architecture đúng hướng cho các epics tiếp theo** — scope-aware foundation của Epic 1 sẵn sàng để Epic 2 build on.
